# Avery 15667 Label Sheet

This document tracks the Avery 15667 label sheet feature for part/job label printing.

## Purpose

The page allows a user to define a part number and job number once in the sidebar, then apply that data across a selected Avery 15667 sheet layout.

## Layout

- Sheet size: Avery 15667- Label size: 0.5" × 1.75"
- Shape: Rectangle- Default layout: 4 columns by 20 rows
- Total labels: 80
- All labels are selected by default
- A deselected row, column, or individual cell shows no printed text

## Controls

- Sidebar inputs:
  - Part Number
  - Job Number
- Master row checkbox:
  - Selects or clears the entire row
- Master column checkbox:
  - Selects or clears the entire column
- Individual label checkbox:
  - Selects or clears a single label
- Select All / Clear All:
  - Applies to the whole sheet
- Print Labels:
  - Opens the browser print dialog for the Avery 15667 sheet

## Behavior

- The entered part and job values are rendered into every selected label
- Deselected rows, columns, and cells remain blank
- The selected label total updates live as the sheet changes
- The page is designed to print cleanly with a label sheet layout

## File

- Frontend page: `public/avery15667.html`

## Possible IPP Printing Implementation

The browser print workflow can remain available as the default option, while a separate server-side print path could send the selected Avery sheet directly to a network printer using IPP (Internet Printing Protocol).

### Proposed Flow

1. The frontend sends the part number, job number, and selected row/column/cell state to a backend endpoint such as `POST /api/avery15667/print`.
2. The backend generates an exact 8.5" × 11" PDF containing the selected labels.
3. Node.js sends the PDF to the configured printer with the `ipp` package.
4. The IPP request specifies the requested paper source, such as the bypass tray.

Example IPP job attributes:

```js
const msg = {
  "operation-attributes-tag": {
    "requesting-user-name": "Tim",
    "job-name": "Avery 15667 Labels",
    "document-format": "application/pdf",
    media: "na_letter_8.5x11in",
    "media-source": "tray-2",
    "media-type": "labels",
    "print-quality": "high",
  },
  data: pdfData,
};
```

### Printer Configuration

- Store the printer IPP URI in server configuration rather than in the browser.
- Query the printer with `Get-Printer-Attributes` before submitting jobs.
- Confirm the printer's exact accepted value for `media-source`; the bypass tray may be named `tray-2`, `manual`, `mp`, `by-pass-tray`, or another device-specific value.
- Confirm whether `media-type: labels` and the requested print quality are supported.
- Handle unsupported attributes and failed jobs with a clear error response.
- Keep the browser print dialog as a fallback when direct IPP printing is unavailable.

### PDF Requirements

The generated PDF must preserve the Avery 15667 physical geometry:

- Page size: 8.5" × 11"
- Left margin: 0.19"
- Top margin: 0.5"
- Label size: 1.75" × 0.5"
- Horizontal pitch: 2"
- Vertical pitch: 0.5"
- Four columns by twenty rows
- Blank output for deselected rows, columns, and cells
- No testing borders around printed labels

A direct PDF library would provide deterministic physical coordinates. A headless browser such as Playwright or Puppeteer could also render the existing print document to PDF, but its page and margin settings would need to be verified carefully.

### Open Questions

- What is the printer's actual IPP endpoint and does it require authentication?
- What exact IPP value selects the bypass tray on the installed printer?
- Should direct printing be a separate button or replace the current browser print button?
- Should the server restrict which users or machines may submit print jobs?

## Notes

The feature is intentionally kept simple and deterministic so it can be used as a first pass for part labeling before a backend or database-driven print workflow is added.
